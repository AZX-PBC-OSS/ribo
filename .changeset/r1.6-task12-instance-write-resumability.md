R1.6 Task 12 — per-instance write resumability

`ToolAdapter.write` is unchanged, but a new sibling composition, `toInstanceWriteStep`, writes each collection instance separately. Each instance receives a deterministic idempotency key derived from the item key, the group and the instance position, so a retry re-derives the same key for the same instance. Progress is persisted incrementally in `OutboxDocument.writtenInstances`, so a retry resumes after instances that already succeeded rather than replaying them.

`Outbox.submitReview` resets `writtenInstances` on every fresh submission, and `reopenForReview` clears any stale progress. The outbox schema version bumps to 5 with an identity migration for the new optional field.
