R1.6 Task 12 — per-instance write-back

`ToolAdapter.write` is unchanged, but a new sibling composition, `toInstanceWriteStep`, writes each collection instance separately. Each instance receives a deterministic idempotency key derived from the item key, the group and the instance position, so a retry re-derives the same key for the same instance and a vendor honouring `Idempotency-Key` recognises it rather than creating a second record.

An earlier revision of this change also persisted per-instance progress so a retry could skip instances that already succeeded. That marker was positional, and position is not identity — it is removed before release rather than shipped. See the session-ownership changeset.
