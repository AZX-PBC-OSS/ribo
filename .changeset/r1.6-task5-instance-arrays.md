R1.6 Task 5 — model Snugg Pro's per-instance resources as arrays in the capture schema.

`hvac`, `attic`, `wall`, `window`, and `dhw` are now `z.array(...).optional()` in
`snuggValuesSchema`, because Snugg Pro creates one child record per element via
`POST /jobs/{jobId}/<type>`. `basedata` and `health` remain singleton objects.

`enveloped()` already recursed into arrays and `splitExtractionSchema` already
preserved array wrappers, so this change is limited to:

- `schema.ts` — the five groups become arrays;
- `examples.ts` — the few-shot example wraps the same leaf values in arrays;
- all test walkers that enumerate leaves or span-grounding now recurse into arrays;
- the frozen JSON Schema fixture is regenerated from the new schema.

The two round-trip tests are skipped because `review.ts` does not yet enumerate
array instances (Tasks 6-7). `requiredOnCreate` is intentionally untouched
(Task 8).
