# The Snugg Pro transcript corpus — migration notes

This corpus is the spike's Snugg Pro dictation corpus, re-expressed in the generic corpus
format that `@azx/ribo-cli`'s `loadCorpus` reads. The source is
`docs/spikes/0001-extraction-snuggpro/` — its real dictation transcripts and their
human-annotated ground truth in the spike's `snuggpro-instances-v3` format — and it was
migrated here read-only: the spike directory is untouched, and the current quality gate keeps
running against it. The manifest declares `provenance: "real"` and names the adapter's shipped
JSON Schema file (`dist/extraction.schema.json`, generated by the package build). The manifest's
prompt inputs are derived from the adapter's own constants (`snuggProInstructions`,
`snuggExamples`), with `fieldDescriptions: "schema"` — the mode core defaults to and the one the
gate's extractor runs under — so a run record's fingerprint computed over this corpus is a
fingerprint over the same measurement the gate makes. `acceptance/corpus.test.ts` recomputes
every expected value from those constants on every run; nothing in the manifest is re-typed by
hand.

This file records the translation rules the migration applied, the gaps the corpus format could
not express (recorded, never fixed by widening the loader — loader changes are their own
ticket), and the narrowings the migration produced. It is the reviewer's map: every decision
below is mechanical and re-derivable from the spike's own files.

## Translation rules

- **Case identity.** Each spike file `ground-truth/NN-slug.json` becomes a case directory
  `NN-slug/` — the case id equals the directory name (the loader's own rule). The case declares
  one `inputs` entry: `{ "file": "input.txt", "kind": "transcript" }`, and `input.txt` is a
  byte-for-byte copy of `transcripts/NN-slug.txt` (the copy-fidelity test keeps it honest). No
  `capture` block: only a document entry carries one.
- **Singleton leaves.** The spike's top-level `leaves` entries (the singleton groups, keyed by
  already-dotted paths) map key for key. An `asserted` entry's `member` (an enum's literal
  string) or `value` (a number or string) becomes the generic entry's `value`; `sourceSpan` is
  copied when the spike's is non-null. A `declared_absent` entry becomes
  `{"status": "declared-absent", "sourceSpan": …}`. Explicit `unmentioned` entries carry no
  information beyond the default and simply produce no key.
- **Collection-group leaves.** The generic scorer reads a collection leaf's produced value as
  the dense list of the instances' non-null values in array order, and an asserted expectation
  for it as a plain object keyed by ordinals, read in numeric order. So for each leaf of a
  collection group (hvac, attic, wall, window, dhw), the asserted values across the case's
  **current** instances in first-mention order become `{"0": v0, "1": v1, …}`, dense in that
  order. Instance-local leaf keys become the dotted path `<group>.<key>`.
- **Excluded instances.** An instance whose `eligibility` is not `current` (a decommissioned or
  off-property unit) carries empty leaves by the spike's own rule and is not represented. Every
  excluded instance in the spike is last in its group's list — the migration asserts that per
  case (it is what makes the dense renumbering faithful). If a future re-annotation ever places
  an excluded instance earlier, the current instances after it renumber contiguously and the
  case must be re-reviewed.
- **Per-instance `declared_absent` widens to leaf level.** The spike records an absence on one
  instance; the generic format addresses the collection leaf once, so the entry forbids the
  value on every current instance of the case. Today no leaf is asserted on one current instance
  and declared absent on another, and no declared-absent leaf carries two different spans across
  instances — the migration asserts both — so the widening loses nothing. It is faithful where
  it matters most (case `08`: no fuel is stated for either unit, so `hvac.hvacHeatingEnergySource`
  and `hvac.hvacHeatingSystemModelYear` are forbidden on both).
- **`arguable.acceptableAlternatives` → `alternatives`.** A plain value on a singleton leaf; on
  a collection leaf, one single-key ordinal object per alternative (`{"<dense position>": alt}`),
  the shape the scorer's per-element alternative rule reads. `symmetric` and the arguable `note`
  have no generic slot — every note is quoted against its case under "Per-case annotations"
  below.
- **Disclaimers → generic defaults or explicit entries.** A spike disclaimer is a verbatim span
  plus a mechanical scope; the spike's resolution policy (`disclaimer-policy.mjs`) turns a scope
  into per-leaf default truths, and the migration consumes its output:
  - A **group** scope (`{kind: "group", group: g}`) becomes a generic default
    `{"scope": g, "status": "declared-absent", "sourceSpan": <span>}` — the policy's output for
    every non-health leaf is `declared_absent`, which is exactly the generic declared-absent
    default's meaning.
  - The **`blowerDoor`** and **`shell`** named sets become declared-absent defaults whose scope
    is the spelled-out leaf paths / path prefixes listed under "Named sets" below — same policy
    output, same meaning.
  - The **`healthTests`** named set is different: the spike's policy ASSERTS the member
    `"Not Tested"` on every health-matrix leaf a blanket "no tests" statement covers (an
    explicitly-skipped test is real, gradable information — see the spike's
    `ground-truth-format.md`). The generic default vocabulary cannot assert a value (its
    defaults are `declared-absent`/`unmentioned` only), so the migration expands the disclaimer
    into explicit per-leaf asserted `"Not Tested"` entries instead of a default. This preserves
    the spike's resolved ground truth exactly — under a declared-absent default, a run correctly
    answering `"Not Tested"` would be graded as a hallucination, which would change what the
    corpus measures.
- **`retracted`** (case `11`, on `hvac.hvacSystemEquipmentType` and `attic.atticInsulation`):
  the retracted value is simply not the asserted final value, so a run producing it scores
  `wrong`. The spike's "wrong because retracted" distinction is retired with the retired verdict
  vocabulary; the rule is stated here once and applied silently by the migration.

## Named sets, as used here

The spike's three named sets, with the membership the migration used and the rule each came
from:

- **`healthTests`** — the pass/fail/warning/not-tested matrix leaves, derived by the spike's
  `schema-leaves.mjs` as every enum leaf whose members are exactly the health-test states. The
  membership used: `health.healthAmbientCarbonMonoxide`, `health.healthNaturalConditionSpillage`,
  `health.healthWorstCaseDepressurization`, `health.healthWorstCaseSpillage`,
  `health.healthUndilutedFlueCo`, `health.healthDraftPressure`, `health.healthGasLeak`,
  `health.healthVenting`, `health.healthMoldMoisture`, `health.healthRadon`,
  `health.healthAsbestos`, `health.healthLead`, `health.healthElectrical`. The prefix `health`
  is deliberately NOT used as a scope: it would wrongly sweep in
  `health.healthRoofCondition`, a visual condition judgement rather than a test.
- **`blowerDoor`** — the two basedata leaves about the blower-door reading:
  `basedata.blowerDoorReading`, `basedata.blowerDoorTestPerformed`. The whole `basedata` group
  would over-reach into `yearBuilt` and friends.
- **`shell`** — the building envelope: the path prefixes `attic`, `wall` and `window`, plus the
  blower-door pair above. Justified by the spike's own corpus text (case `06`: "Attic and the
  REST OF THE SHELL we'll do on the next visit").

## Documented gaps

Each gap below is an omission the corpus format forced, recorded here rather than fixed by
widening the loader. What the format would need is stated per gap; a loader change to express
any of them is its own ticket.

1. **`arguable.acceptableMiss: true` — omitted from `expected`.** The generic taxonomy has no
   excused miss: the design's translation table maps the spike's `miss-excused` to
   `unscorable`, "not judged, counts in no denominator", so the leaf is omitted (unmentioned →
   not judged). The known loss: the spike still graded a _produced_ value on such a leaf; this
   corpus does not. What the format would need: a per-entry "absence is acceptable" marker.
   The leaves omitted under this rule, per case: `03` `window.windowType`; `05`
   `hvac.hvacUpgradeAction`, `hvac.hvacDuctLocation`, `attic.atticInsulation`,
   `dhw.dhwLocation`; `06` `health.healthAsbestos`; `08` `hvac.hvacHeatingSystemModel`,
   `hvac.hvacDuctLocation`; `10` `dhw.dhwLocation`; `11` `health.healthAmbientCarbonMonoxide`;
   `13` `health.healthAmbientCarbonMonoxide`.
2. **`noFittingMember` — omitted from `expected`.** One leaf: `07` `dhw.dhwLocation[0]` — the
   auditor says "the utility room", and no member of the location enum fits. No asserted enum
   expectation can represent a non-member (the membership test exists precisely to refuse one),
   so the leaf is omitted. Nothing is lost that the format could hold: this is the schema's
   closed enum, and the annotation is a schema finding for the adapter, not a corpus entry.
3. **The `unresolved` disclaimer in `03`** ("nothing on the inside today"). It reaches no leaf
   by definition, and a generic default that covers no leaf is refused by the loader. Dropped
   and recorded; the spike's file keeps it as data.
4. **Excluded-instance nuance.** The corpus grades exclusion implicitly: a run that extracts an
   excluded unit produces extra values, and the length-mismatch rule marks every asserted leaf
   of the group `wrong`. The spike's finer distinction — "silently dropped" vs "never noticed"
   — is not gradable in the generic format.
5. **Partially-asserted collection leaves in `05` and `08`.** Because a collection leaf's
   expectation holds only the asserted instances, dense from zero, a run that answers such a
   leaf on the _other_ current instance scores `wrong` where the spike stayed silent, and
   cross-instance attribution of a partially-asserted leaf is not graded. The spike's
   assertions are kept as they are. The leaves involved — `05`: `hvac.hvacUpgradeAction`,
   `hvac.hvacHeatingEnergySource`, `hvac.hvacHeatingSystemManufacturer`,
   `hvac.hvacHeatingSystemModel`, `hvac.hvacHeatingSystemModelYear`, `hvac.hvacHeatingCapacity`
   (asserted on the furnace instance only) and `hvac.hvacDuctLocation`, `hvac.hvacDuctLeakage`,
   `hvac.hvacDuctLeakageValue`, `hvac.hvacDuctInsulation` (asserted on the AC instance only);
   `08`: `hvac.hvacHeatingSystemManufacturer` and `hvac.hvacHeatingSystemModel` (furnace only)
   and `hvac.hvacDuctLocation`, `hvac.hvacDuctLeakage`, `hvac.hvacDuctInsulation` (AC only).
   (Some of these are simultaneously gap 1 omissions; the narrowing applies to whichever
   survive.)
6. **The few-shot example's format losses.** `snuggExamples`'s single worked example is the full
   enveloped shape: two hvac instances (an oil boiler and a separate Carrier heat pump — the
   "two systems, primary unstated" lesson), several envelopes with a confidence other than 1,
   many non-null `sourceSpan`s, and an explicitly empty `pv` group. The manifest's flat
   `{transcript, fields}` example can hold none of those: the runner's translation emits exactly
   one array element per collection group, no envelope metadata travels, and an empty group
   contributes nothing. The derivation rule the migration (and the parity test) applies: the
   transcript verbatim; `fields` = every leaf envelope flattened to `dotted.path → value`,
   **null-valued envelopes included** (the honest-null lesson is the anti-hallucination
   discipline this corpus exists to measure and must survive); for arrays, the **first**
   element's leaves only; empty arrays contribute nothing. What the format would need:
   per-instance example values and envelope metadata.

## Narrowings the migration produced beyond the gaps

- **Case `05`, `dhw.dhwAge`: alternatives on a declared absence cannot travel.** The spike
  records `declared_absent` (with a span) plus `arguable.acceptableAlternatives: ["0-5"]` — a
  model reading "it's newer though" as the youngest band was to be tolerated. The generic
  `declared-absent` entry refuses an `alternatives` key, so the tolerance is dropped: a run
  producing `"0-5"` scores as a hallucination where the spike excused it. Quoted in full under
  "Per-case annotations". The format would need the same per-entry alternative slot the
  asserted status already has.

## Vocabulary coverage

The live schema's field vocabulary is broader than the pilot subset the spike annotated, so
leaves outside that subset are unmentioned by construction (augmenting them is re-annotation, a
later reviewed change). The migration is reformatting plus the translations
above, not vocabulary repair: every case's leaf paths and enum members resolve against the
converted shipped schema, and the corpus's own test walks every asserted value and alternative
against the schema's leaf inventory on every run.

## Per-case annotations

The spike's `arguable` notes have no generic slot; they are quoted here against their case,
kept and omitted alike, so a reviewer can read the annotator's reasoning without the spike's
format. Anything not listed below migrated mechanically.

### `01-attic-r-value-shell`

  conflated-axis pattern as ANNOTATOR_GUIDE.md rule 6 / the worked example. 'Heat's a gas

### `05-full-walkthrough`

- `hvac.hvacSystemEquipmentType` (kept): "SCHEMA CARDINALITY COLLISION, a different shape than
  the worked example's axis conflation (not marking symmetric: this is not a same-phrase
  tie-break). The transcript narrates TWO fully independent, standalone-duct systems in full
  detail: 'The heating system is a propane furnace...' (make/model/year/capacity), AND 'Cooling
  is central AC, it's got a standalone air handler up in the attic with its own duct runs... So
  central AC, standalone ducts.' hvac.hvacSystemEquipmentType has only one write slot --
  schema.ts's own file header admits this cardinality gap ('a single dictation... A second
  system dictated today lands on the same leaves as the first and the reviewer sees the
  collision.'). Because the auditor explicitly states the AC's ducts are standalone (not shared
  with the furnace), 'Furnace / Central AC (shared ducts)' is actually RULED OUT here, not
  merely unaddressed. 'Furnace with standalone ducts' is chosen as member because the furnace is
  the system given full equipment detail AND the auditor's own words single it out as 'the
  system' ('The working system, the one that heats this house today, is the propane Carrier in
  the closet'); the central AC is a real, independently-detailed competing system, not a wrong
  answer, hence acceptableAlternatives. hvac.hvacDuctLocation/hvacDuctLeakage/
  hvacDuctLeakageValue/hvacDuctInsulation below describe the AC's attic ductwork specifically,
  not the furnace's -- this file's hvac.* leaves, taken together, describe two different
  physical systems, which the schema's single-instance shape cannot avoid. Schema finding, not a
  resolvable transcript ambiguity -- see RECONCILIATION.md."
- `hvac.hvacUpgradeAction` (omitted, gap 1): "Two things are contested. First, ATTRIBUTION: this
  is the auditor's own sentence, not a bracketed second-speaker line, but it reports a plan the
  HOMEOWNER already set in motion ('the homeowner's got a quote') rather than the auditor's own
  explicit recommendation (schema.ts's own example is 'we should get rid of it') -- genuinely
  between 'the auditor is recommending this' and 'the auditor is just relaying an existing
  plan', so a model that leaves this leaf null given that attribution doubt is a defensible
  caution (acceptableMiss). Second, FIT: none of the four members say 'replace with a DIFFERENT
  equipment family' -- swapping a furnace for a heat pump is a bigger change than 'a newer
  model' of the same thing usually implies -- but it remains the closest real member: 'Remove a
  system permanently' does not fit, because a replacement (the heat pump) IS planned, not a bare

  noFittingMember, since a real member is defensibly close, not absent."

  it is conditioned, and hvacDuctLocation pairs every place with that. Attic (unconditioned) is
  the likely truth, but the leaf is told to abstain (value null, span kept) when only a place is
  named, so a null here follows the instruction rather than missing a stated answer."
- `attic.atticInsulation` (omitted, gap 1): "Tests the boundary of rule 7's 'if the auditor
  gives both a depth and an R-value, both are asserted independently' instruction against rule

  explicitly self-labels it as a CONVERSION from the measured depth, not an independent
  observation ('the R-value's just the conversion... the depth is what I actually measured'),

  both-depth-and-an-R-value shape and instructs asserting both without converting between them,

  final answer,' this number's own speaker frames it as secondary/derived, so a model that
  leaves it null is a defensible, mild miss rather than a real omission."
- `dhw.dhwLocation` (omitted, gap 1): "Requires two inferential steps the auditor never states
  outright in this sentence: (1) that 'the closet' here is the same 'mechanical closet off the

  heated area' rather than an unconditioned utility space. Per THE ONE RULE, something WAS said
  about location, so omission alone is not the intended default -- but the mapping is genuinely

- `dhw.dhwAge` (kept as declared-absent; its alternative dropped — see "Narrowings"): "The
