On-device extraction — corpus run

Three strategies, each writing to its own results directory. score.mjs reads all three unchanged.

  • Per-group — the production wiring: seven calls, each constrained to a nested object of envelopes.
  • Two-phase — a spike: one call per group for verbatim spans, then one call per non-null span for the leaf value. The hypothesis is that the narrower constraint removes the whitespace loop.
  • Three-phase — a spike: one call per group for a boolean presence gate, then the two-phase span+classify pipeline only for the leaves the gate admits. The hypothesis is that a boolean is easier to answer truthfully than a nullable span, so the model fabricates fewer quotes.

Must be opened in real Chrome. Chromium's Prompt API is a stub that answers with fixed text, so a run there would grade nothing. This page checks and refuses.

Leave the tab focused — a background tab gets throttled. The two-phase and three-phase strategies make many more calls than the per-group one, so they take longer.
